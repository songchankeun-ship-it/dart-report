# DART 공시 자동 리포트 (MVP)

금감원 DART 공시를 긁어서 → 유형 분류·중요도 → 원문에서 수치 추출 → (선택) LLM이 **사실팩 안의 정보만으로** 해석 → 근거·인용 붙은 마크다운 리포트.

```
dart_client.py   DART Open API (기업코드 / 공시목록 / 원문 / 재무제표) + 원문 텍스트 추출
analyzer.py      공시 분류 규칙(RULES), 수치 추출, LLM 프롬프트, 인용·숫자 자동검증
parsers.py       전용 파서 6종: 전환사채(CB/BW/EB)·유상증자·공급계약·최대주주변경·자기주식·감사의견 → 정형 값 + 파생치
report.py        마크다운 렌더링
html_report.py   md → 브라우저용 HTML + reports/index.html 목록 페이지 (외부 패키지 불필요)
alerts.py        신규 공시 폴링 → 텔레그램 알림
riskboard.py     종목별 공시 리스크 보드 (감사의견·CB/BW 잔여 잠재주식·유상증자·최대주주/담보·분기실적·업종비교)
quarterly.py     분기 손익 시계열 (4분기 = 연간 − 3분기 누적, 재작성 의심 ⚠)
industry.py      업종 지도(상장사 전부 company.json, 30일 캐시) + 동종업종 재무 비교
audit.py         정확도 전수 대조 도구 — 시장 전체 최근 공시를 파싱해 '파싱값 | 원문근거 | 확인란' 대조표 + 필드 채움률
pipeline.py      회사 1곳 분석 (main/weekly 공용)
main.py          CLI (회사 1곳)
weekly.py        관심종목 일괄 + 주간 합본
watchlist.txt    관심종목 목록
test_*.py        네트워크 없이 검증: for t in test_*.py; do python $t; done  (Windows: for %t in (test_*.py) do python %t)
```

## 설치

```bash
pip install -r requirements.txt
cp .env.example .env     # 키 채우기
```

- `DART_API_KEY` — https://opendart.fss.or.kr → 인증키 신청 (무료, 즉시 발급, 일 20,000건)
- `ANTHROPIC_API_KEY` — LLM 해석을 쓸 때만. 없으면 `--no-llm` 으로 사실팩 리포트만 생성.

## 실행

```bash
python main.py 삼성전자 --days 7              # 최근 7일 공시, LLM 해석 포함
python main.py 005930 --from 20261001 --to 20261020
python main.py 에코프로 --days 30 --no-llm     # 해석 없이 사실 정리만 (API 비용 0)
python main.py 삼성전자 --days 7 --min-importance 4   # 중요도 4 이상만 LLM 해석
```

결과: `reports/<회사>_<시작>_<끝>.md` + 같은 이름 `.html`(브라우저로 열기) + `.json`(원데이터). `reports/index.html` 이 전체 목록.

### 관심종목 일괄 → 주간 합본

```bash
# watchlist.txt 에 한 줄에 하나씩 (회사명 또는 종목코드, # 주석 가능)
python weekly.py                       # 최근 7일, 중요도 3 이상만 LLM 해석
python weekly.py --no-llm              # 비용 0, 사실 정리만
python weekly.py --days 14 --min-importance 4
```

결과
- `reports/weekly/주간공시_<시작>_<끝>.md` — 합본. 맨 위에 전 종목 통합 "이번 주 핵심 공시(★4 이상)" 표 → 신호 집계 → 종목별 요약표 → 종목별 공시 목록
- `reports/weekly/<시작>_<끝>/<회사>.md` — 종목별 상세 (main.py 와 같은 포맷)

한 종목이 실패해도(회사명 못 찾음, 네트워크 등) 그 줄에 ⚠ 표시만 하고 나머지는 계속 돕니다.

### 전용 파서가 뽑는 것 (리포트 '핵심 수치' 블록)

| 유형 | 원본 값 | 파생치 |
|---|---|---|
| 전환사채(CB/BW/EB) | 권면총액, 전환가액, 최저조정가액, 발행주식수, 주식총수 대비 비율, 이자율, 청구기간, 발행방법, 자금목적, 발행대상자 | 리픽싱 하한비율, 리픽싱 후 최대 주식수·비율, 사모 여부 |
| 유상증자 | 신주 수, 증자전 총수, 증자방식, 확정/예정 발행가, 할인율, 납입일·상장예정일, 배정대상자 | 희석률, 조달예정액, 제3자배정 여부 |
| 공급계약 | 계약금액 총액, 최근 매출액, 매출액 대비 %, 상대방, 계약기간, 조건부 여부, 공시유보 | 계약기간 일수, 연환산 계약금액 |
| 최대주주변경 | 변경 전/후 최대주주·주식수·지분율, 변경사유, 변경일, 양수도 금액, 경영권 변동 여부 | 지분율 변화(%p), 주당 인수가 |
| 자기주식 | 취득/처분/소각 구분, 주식수, 예정금액, 기간, 목적, 방법, 취득 전 보유량 | 주당 예정단가 |
| 감사의견 | 감사의견(적정/한정/부적정/의견거절), 계속기업 불확실성, 강조사항, 감사인, 기수 | 비적정 플래그, 의견변경·재작성 언급 |

금감원 기업공시서식 표준 라벨 기준. 못 찾은 필드는 `None` 으로 두고 절대 추측하지 않으며, 대부분 못 찾으면 `_warning` 을 달아 LLM 확신도를 낮춘다.
**실제 공시를 아직 못 돌려본 상태**라 라벨 변형이 있을 수 있음 — 첫 실행 후 `reports/*.json` 의 `structured` 를 보고 비는 필드를 알려주면 정규식 보강.

### 정확도 검증 (테스트 1) — 서비스화 전 필수

```bash
python audit.py --days 5 --per-type 15      # 시장 전체에서 6개 유형 × 최대 15건 → audit/<날짜>/
```
- `audit.html`: 공시별로 필드 · 파싱값 · 원문에서 그 값이 나온 줄 · 체크박스. 원문 링크 열어서 값이 맞는지 하나씩 확인.
  노란 줄 = 값은 있는데 원문 근거를 자동으로 못 찾음(사람이 꼭 확인), 빨간 줄 = 빈값.
- `fill_rate.md`: 유형별·필드별 채움률. 비율 낮은 필드 = 정규식 보강 대상.
- `audit.csv`: 같은 내용, 엑셀용 (사람확인/메모 열 포함).
- 통과 기준: **틀린 값 0건**. 빈값은 괜찮지만(추측 안 함) 틀린 값은 1건도 안 됨.

#### 1차 전수 대조 기록 (2026-10-20, 시장 전체 7일치 90→100건)
처음 돌렸을 때 발견된 '틀린 값'과 조치:
| 문제 | 원인 | 조치 |
|---|---|---|
| 표 한 행이 여러 줄로 쪼개져 다열 표(대상자·발행가) 전부 누락 | 원문 XML의 줄바꿈 공백을 그대로 둠, DART 전용 TE/TU 셀 태그 미처리 | 추출기 재작성(공백 접기 → 셀 단위 처리) |
| 정정공시에서 '정정 전' 옛 값을 집을 위험 | 정정표가 본문 앞에 옴 | 서식 1번 항목의 마지막 위치부터 본문으로 인식(`form_body`) |
| 감사보고서 15건 중 5건 "계속기업 불확실성" 오탐 | 감사인의 책임 보일러플레이트 문구에 매칭 | 단락 제목/단정문만 인정, 거래소 요약표는 '해당여부' 셀 읽음 |
| 감사의견 4건 미확인 | '제외하고는'이 다른 단락에도 있어 적정 판정 차단 | 의견 문단만 잘라서 판정 |
| 최대주주변경에서 주주명이 '최대주주등'(라벨)로 추출 | 라벨 변형 | 라벨 패턴 추가 |
| 자기CB 취득/매도, 최대주주 담보제공·양수도계약, 소유주식변동신고서에 엉뚱한 파서 적용 | 분류 규칙이 너무 넓음 | 유형 분리 + 전용 파서 3종 추가 |
| 전환사채 발행 '철회' 공시가 빈 양식으로만 보임 | 본문이 전부 '-' | 정정사유에서 철회/취소 감지 → 경고 표시 |
| 유상증자 할인율 부호가 회사마다 반대 | 공시 기재 관례 불일치 | 기준주가에서 직접 계산, 기재값과 1%p 이상 다르면 ⚠ |

현재 상태: 수정 후 전 유형 결과를 사람이 훑어 **틀린 값 미발견**. 단, 사람 눈 검토는 요약 라인 기준이라 Song이 `audit.html`로 샘플 15~20건 원문 대조를 한 번 더 하는 걸 권장.
남은 빈 필드: 소규모 회사 감사인(감사반/개인), 공급계약 조건부 금액(대부분 '-'), 양수도계약 해제·취소(전용 파서 없음), 타법인주식취득(파서 없음, ★4라 다음 후보).

### 종목별 리스크 보드

```bash
python industry.py build                       # 처음 1회 (60~90분, 이후 30일 캐시). run_daily.bat 이 없으면 자동 실행
python riskboard.py --watchlist watchlist.txt   # reports/stocks/<종목>.html
```
- 주의 신호: 감사의견 비적정·계속기업 불확실성 / CB·BW 잔여 잠재주식 10%·20% / 유상증자 누적 30% / 최대주주 담보 50%·지분 15% 미만 /
  불성실공시·회생·횡령 / 4분기 연속 영업적자·매출 2분기 연속 −20%·자본잠식·부채비율 300% / 업종 하위 10% (영업이익률·부채비율)
- 기준값은 표시 규칙일 뿐 투자 판단이 아니며 리포트에 값과 함께 노출됨.
- CB 잔여 잠재주식 = 회차별 (최신 전환가액조정 공시 미전환 잔액 | 발행 권면) − 이후 회사 취득 + 재매각, ÷ 리픽싱 하한가. 일반 전환청구분 미반영(최대치 쪽 추정).
- 4분기 손익은 DART에 없어 연간 − 3분기 누적으로 도출. 재무제표 재작성 회사는 어긋날 수 있어 ⚠ 표시 후 신호 판정 제외.

### 실시간 알림 (텔레그램)

```bash
python alerts.py --once --dry-run          # 콘솔 출력으로 테스트
python alerts.py --once                    # 1회 확인 후 종료 → 작업 스케줄러에 10분 간격으로
python alerts.py --interval 600            # 데몬처럼 반복

```

- 텔레그램 설정: @BotFather 로 봇 생성 → `TELEGRAM_BOT_TOKEN`; 봇에게 아무 메시지 보낸 뒤 `https://api.telegram.org/bot<TOKEN>/getUpdates` 에서 `chat.id` → `TELEGRAM_CHAT_ID` (.env 에)
- 알림 내용: 중요도·종목·공시명·유형 + 전용 파서 핵심 수치(최대 5줄) + (`--llm` 시) 한 줄 해석과 확인 포인트 + DART 원문 링크 + 면책
- `.alert_state.json` 에 보낸 접수번호를 기록해 중복 없음. 첫 실행 때는 과거 공시를 전부 기전송 처리(폭주 방지)
- API 사용량: 종목 수 × (하루 ÷ 간격). 20종목 10분 간격 ≈ 2,900회/일 (한도 20,000)

## 설계 포인트 (왜 이렇게 짰나)

1. **숫자는 LLM이 만들지 않는다.** 원문/재무 API에서 파싱한 값만 사실팩에 넣고, LLM은 해석·구조화만.
2. **자동 검증.** LLM이 돌려준 인용문이 원문에 그대로 있는지, 언급한 숫자(300억 → 30,000,000,000 환산 포함)가 원문에 있는지 코드로 대조. 하나라도 틀리면 인용 삭제 + 확신도 '낮음' + 리포트에 경고 표시.
3. **추천 금지.** 프롬프트에서 매수/매도/목표가 표현을 금지하고 signal 은 긍정적/부정적/중립/판단보류 4단계로만. 리포트 상단에 면책 문구 고정.
4. **맥락 제공.** 같은 회사의 과거 유사 공시(기본 3년) 링크를 자동으로 붙임 → "이 회사 CB 발행이 처음인지, 세 번째인지"가 보임.
5. **모든 항목에 DART 원문 링크 + 접수번호.** 사용자가 1클릭으로 검증 가능.
